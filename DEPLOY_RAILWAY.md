# Шалт — перенос на GitHub и Railway

Исходная версия: Sites, версия 3, commit `09decfa0adb699617c61147c55659ef2b7b89b34`.
Включены последние изменения интерфейса: компактные показатели, общий блок карты и времени, исправленное раскрытие задания.
Игровой код и рисунки перенесены без изменений. Добавлены только настройки запуска вне Sites.

## GitHub

Репозиторий: `Berg47/shalt-mountain-path`, ветка `main`.
В корне репозитория должны лежать `package.json`, `package-lock.json`, `railway.json`, `index.html`, папки `src`, `public` и `tests`.
Не загружайте ZIP как единственный файл: архив нужно распаковать и загрузить его содержимое.

## Railway

Подключите GitHub-репозиторий `Berg47/shalt-mountain-path`, ветку `main` как источник сервиса игры.
Не используйте проекты, репозитории или домены Жаргата.
Root Directory: корень репозитория. Config as Code: `/railway.json`.
Сборка: `npm run build`. Запуск: `npm start`. Проверка доступности: `/`.
Railway устанавливает зависимости из `package-lock.json`; пакет `serve-handler` входит в обычные зависимости. `server.mjs` раздаёт только собранный каталог `dist`.
Сервер слушает `0.0.0.0` и порт из `PORT` (локально по умолчанию 3000).
После успешного запуска создайте Railway-домен с портом, на котором запущен сервис.
При использовании старого сервиса удалите прежнюю команду проксирования Sites и источник Docker image: нужен источник GitHub.

## Проверка локально

```sh
npm ci
npm run build
npm start
```

Откройте `http://localhost:3000`. Для разработки используйте `npm run dev`.

## Сохранения

Прогресс хранится в localStorage браузера и привязан к адресу сайта. На новом Railway-домене старое сохранение Sites автоматически не появится.
Старую публикацию Sites этот перенос не удаляет.
